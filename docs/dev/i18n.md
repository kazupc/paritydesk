# Messages

paritydesk prints English only. Every text a person reads is a message in
the English catalog (`internal/i18n/catalog.go`), keyed by an id. The
plugin's skills talk to the user in the language the user writes in and
translate what paritydesk prints, line by line, keeping numbers, names,
ids, codes and commands unchanged. The repository holds no translations
and no Japanese text (`TestRepoIsEnglishOnly`); tests that need non-Latin
sample text (display widths of session titles, for example) write it as
`\u` escapes.

## Rules

1. Messages are late-bound: `i18n.Tx(id, args...)` builds an `i18n.Text`;
   structs that reach JSON hold `i18n.Text` (it encodes its text). Human
   output renders it with `Printer.Msg`, `Printer.Text` or
   `Printer.Render`, which sanitize the arguments, never the format.
2. `pderr.New` with a message is not used outside tests: use
   `pderr.NewT`/`pderr.WrapT` for what a person can act on, and
   `pderr.Bug`/`pderr.Bugf` for broken invariants.
3. Command-line errors use `usageError(id, args...)`.
4. No `i18n.T(id, "%s")` re-format pattern, and the first argument of
   `Printer.Line` is a constant format.
5. Actionable error texts of other packages are `i18n.NewErr` sentinels
   or `i18n.WrapErr`.
6. `i18n.Register` is called only in `internal/i18n`.
7. No string literal is assigned to a field named `Problem`, `Detail`,
   `Message`, `Warnings`, `Lines` or `Actions`.

`TestUserTextFromCatalog` in `internal/policy` checks rules 2 to 7;
`internal/i18n` checks that every id has a text and that the catalog is
printable ASCII; `TestHelpTextsAreMessages` in `internal/cli` checks that
command short texts and flag usages are catalog ids.
