# Messages and languages

This page is for contributors. It describes how paritydesk chooses the
message language, what stays English, and the rules and tests every
message follows. The Japanese style guide and glossary are the comment at
the top of `internal/i18n/catalog_ja.go`.

## Choosing the language

Highest first: `--lang` (`auto`, `en`, `ja`, any ASCII case) >
`PARITYDESK_LANG` > config `[ui] lang` > the locale (`LC_ALL`, then
`LC_MESSAGES`, then `LANG`; the first non-empty one wins; its language part
must be `ja`) > config `[ui] fallback_lang`, used only when all three
locale variables are empty > English. `auto` or empty means "not set
here". An invalid `--lang` is a usage error (exit 2); an invalid
`PARITYDESK_LANG` is ignored with one warning; invalid `[ui]` values are
ignored when choosing and reported by `config validate`. The `[ui]` keys
are read by a tolerant reader (`config.ReadUI`), so the language works even
when the rest of the config is invalid.

Each process has two languages:

- the display language (the choice above), used only for the
  `display_lines` member of JSON documents and the `display_*` members of
  questions;
- the process language, which renders every human line: the choice above,
  but English under `--json`, in ASCII mode (`--ascii`, `TERM=dumb`, a
  locale that is not UTF-8), for `hook`, `completion` and the hidden
  aliases command, and for the detached job and the background check.

`init` writes `[ui] fallback_lang = "ja"` when its language came from the
locale or `PARITYDESK_LANG` (Code sessions started from the Dock usually
have no locale, so the plugin gets Japanese `display_lines` this way). It
never writes `[ui] lang` and never persists a `--lang` flag.

## What stays English

Every JSON key and value (except the additive `display_lines`), NDJSON
progress, run logs, the support archive, the detached job's
notifications, error ids `PD-E<n>`, exit codes, identifiers inside prose
(commands, flags, aliases, categories, rows, phases, status words, check
ids, modes, file names), model-facing hook text (`hook.*`, `guard.*`),
plugin skill files, completion scripts and every document except
`README.ja.md`.

## Rules

1. Messages are late-bound: `i18n.Tx(id, args...)` builds an `i18n.Text`;
   structs that reach JSON hold `i18n.Text` (it encodes the English text).
   Human output renders it with `Printer.Msg`, `Printer.Text` or
   `Printer.Render`, which sanitize the arguments, never the format.
2. `pderr.New` with a message is not used outside tests: use
   `pderr.NewT`/`pderr.WrapT` for what a person can act on, and
   `pderr.Bug`/`pderr.Bugf` (English) for broken invariants.
3. Command-line errors use `usageError(id, args...)`.
4. No `i18n.T(id, "%s")` re-format pattern, and the first argument of
   `Printer.Line` is a constant format.
5. The hook package uses `i18n.En` and English-only ids only.
6. Actionable error texts of other packages are `i18n.NewErr` sentinels
   or `i18n.WrapErr`; their `Error()` stays the English text.
7. `i18n.Register`/`RegisterIn` are called only in `internal/i18n` and
   `internal/pderr`.
8. No string literal is assigned to a field named `Problem`, `Detail`,
   `Message`, `Warnings`, `Lines` or `Actions`.
9. A Japanese format uses the same verbs per argument as the English one
   (explicit indexes such as `%[2]s` may reorder them); at run time an
   incompatible entry is never used.

## Tests

- `internal/i18n`: completeness (`TestJapaneseComplete`), no stray keys,
  format verbs, layout (leading spaces, `[y/N] `), protected tokens
  (flags, file names, `PD-E`, docs paths, environment names), style
  (punctuation, spacing, no advice to end an account's session), order,
  the language order (`TestResolve`), the fallbacks of `TIn`, `Text` and `List` JSON,
  `i18n.Error`, and a property test of every format in both languages.
- `internal/render`: display widths, truncation, the Japanese table and
  error frame (goldens under `testdata/ja/`), `PlanLinesIn`, `doctor`'s
  free last column, redaction of late-rendered arguments.
- `internal/cli`: help ids (`TestHelpTextsAreMessages`), Japanese usage,
  human and JSON goldens under `testdata/ja/`, JSON language invariance,
  forced English, `--lang` positions, `[ui]` without a locale, `init`,
  answer folding, commands kept in Japanese text, language restore, the
  hook reading nothing.
- `internal/policy`: `TestNoUntranslatedLiterals` (rules 2 to 8),
  Japanese letters only in the allowed files, the private deny-list
  checked inside Japanese text, the error catalog in Japanese, no
  Japanese advice to end an account's session, and the skills'
  `display_lines` rule.
